# ПР11. Спостережуваність і контроль ресурсів AI-компонента

Реалізація матеріалів до одинадцятої практичної роботи. Застосунок має локальний підставний провайдер `mock`, тому його можна запустити й перевірити без Gemini/OpenAI API-ключа. Для справжнього OpenAI-сумісного провайдера окремо змініть налаштування у `.env`.

## Задача коротко

Помічник оператора «Сузірʼя» з ПР10 працює — і до вас прийшли з питаннями: скільки коштували чернетки минулого тижня, чому вчора о 14:00 було повільно, чому чернетка Петренка тричі впала, чому за одне звернення заплачено пʼять разів, і хто гарантує, що місячний бюджет ключа не буде перевищено. Застосунок ПР10 не відповість на жодне: журнал подій живе в браузері, реєстр — у памʼяті до перезапуску, uvicorn пише лише `POST /api/drafts 202`.

У цій роботі застосунок ПР10 **доповнюється**, а не переписується: **структурований журнал** (JSON lines) з **ідентифікатором запиту**, провайдером, моделлю, **версією prompt**, тривалістю, статусом, видом збою, токенами й **вартістю** кожного звертання; **кеш відповідей** з обходом за кнопкою «Повторити»; **денний ліміт витрат** з попередженням і відмовою; **аналіз журналу** — повільні, невдалі, повторні, витрати, влучання; **порівняння з кешем і без** на одному потоці замовлень.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Реалізація вебзастосунку, провайдерів, кешу, бюджету й журналу |
| `samples/requests.json` | Ті самі вісім звернень, що в ПР10 |
| `requirements.txt` | Залежності роботи (ті самі, що в ПР10) |
| `.env.example` | Зразок налаштувань: усе з ПР10 + журнал, ціни, кеш, ліміт |
| `check_env.py` | Перевірка Python, пакетів, налаштувань, папок та зразків; реальний провайдер перевіряється лише за його вибору |
| `eval/` | Сценарії, прогін замовлень через API та аналіз журналу |

```
app/
├─ main.py                HTTP API, X-Request-ID, контрольовані помилки
├─ telemetry.py           структурований JSON-lines журнал
├─ costs.py               тарифікація usage та позначення оцінок
├─ cache.py               TTL-кеш на диску з обходом fresh
├─ budget.py              UTC-ліміт витрат і резервування
├─ providers/             реальний OpenAI-сумісний адаптер і локальний mock
├─ gateway.py             спроби, таймаути, кеш, бюджет, потокові відповіді
├─ jobs.py                фонові чернетки, скасування й кореляційні події
├─ limits.py              обмеження частоти на клієнта
├─ drafting.py            версія та складання prompt, перевірка чернетки
└─ templates/index.html   інтерфейс оператора, витрати, кеш і статуси
eval/
├─ README.md              сценарії, що фіксувати, питання для висновків
├─ replay.py              прогін замовлень через API з повторами — готовий
└─ analyze.py             повільні/невдалі/повторні виклики, витрати й кеш
```

Режим `mock` бере готові відповіді з `samples/requests.json` і працює без мережі та ключа. Вартість mock-викликів за замовчуванням моделюється за тими самими цінами, що й реальні виклики.

## Початок роботи

1. **Середовище:**

   ```bash
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   copy .env.example .env
   ```

   Для macOS і Linux активація середовища — `source .venv/bin/activate`, копіювання — `cp .env.example .env`. Типова конфігурація `LLM_PROVIDER=mock` не потребує ключа доступу. Якщо потрібен реальний провайдер, оберіть його в `.env` і збережіть ключ тільки там; не додавайте `.env` до репозиторію.

2. **Перевірка:**

   ```bash
   python check_env.py
   ```

   Для локального mock ключ не потрібен, `.env` необовʼязковий. Скрипт перевіряє середовище й підготовлює папки. Пробний мережевий виклик робиться лише тоді, коли вибрано реальний провайдер.

Запуск застосунку з папки `pr11`:

```bash
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000 — сторінка працює з підставними відповідями з `samples/requests.json`. Журнал пишеться в `logs/app.jsonl`, кеш і бюджет — у `state/`.

## API і сторінка

`POST /api/drafts` приймає `{"request_id": "d01", "client": "…", "fresh": false}`; кнопка «Повторити» надсилає `fresh: true`. Сторінка показує вартість, токени фактичного виклику, кеш-хіти, бюджет і request ID помилки. `GET /api/usage` повертає стан бюджету, статистику кешу й ціни.

## Реалізовані можливості

| Де | Поведінка |
|---|---|
| Журнали | JSONL-події з request/draft IDs, спробами, часами, моделлю, usage, вартістю та видом помилки; без prompt, клієнтських даних і секретів |
| Шлюз | Кеш перед генерацією, резервування бюджету, обмежена конкурентність, таймаути, повтори лише до першого фрагмента, запасний провайдер |
| Кеш і бюджет | SHA-256 ключ за вмістом/параметрами/prompt version; TTL і атомарне сховище; UTC-ліміт з атомарним файлом та резервом на паралельні виклики |
| Провайдери | `mock` без мережі/ключа; OpenAI-сумісний адаптер з обробкою помилок і usage у streaming |
| Аналіз | `eval/analyze.py` показує повільні, невдалі, повторні виклики, витрати та кеш-хіти |
| Перевірка | Інтеграційні сценарії та однакова послідовність `eval/replay.py` для порівняння кешу й обходу |

`eval/replay.py` використовує частіше опитування стану, щоб затримка вимірювання не приховувала виграш від кешу. Реальний Gemini/OpenAI endpoint тут не тестувався: для нього потрібні власні облікові дані та окремо налаштований `.env`.
